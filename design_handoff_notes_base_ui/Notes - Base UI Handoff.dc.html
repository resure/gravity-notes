01

What I read, what I assumed

Read from the screenshots
  • Three panes: folder tree (counts, nesting, New Folder), note list (folder filter, sort, New), editor.
  • Title bar carries sync dot, global search/create, overflow menu — window is frameless.
  • Editor is a block editor: drag handle, insert button, block context menu, tables, code, headings, a metadata line.
  • Per-note appearance overrides on top of workspace overrides on top of app defaults — three levels.
  • Footer disclosure: N linked references.
  • Focus mode hides both side panes.
Decisions taken from you
  • Three-pane shell stays. No Things-style merge.
  • List row keeps title, time, pin and a one-line preview — the breadcrumb goes; a quiet scope header names the folder instead.
  • Search stays always-visible in the title bar.
  • Light and dark are both first-class; dark is ink, not gray.
  • One accent — amber. It is the brand, not a setting; selection stays neutral.
  • PT Serif, bundled, is the one webfont: note titles, section headings, the editor’s serif option. Cyrillic is first-class.
  • Appearance inherits app default → per-note. The workspace level is cut.
  • Focus mode hides the panes; the title bar and search stay.
  • iOS first for mobile; Android inherits the tokens later.
Assumed — tell me if wrong
  • Notes are markdown files on disk; folders are real directories. Nothing here needs a server.
  • The block editor stays (TipTap/ProseMirror-class). Base UI supplies chrome around it, not the editing surface.
  • The list is virtualized at thousands of rows, so fixed row height is a requirement, not a style choice.
  • macOS is the lead desktop target; Windows gets the same layout with its own title bar inset.
  • No multi-user, no comments, no presence.
02

Five rules the whole app obeys

You asked for material and depth, and for craft in the small. Those are not decoration here — they are the two rules that decide every surface and every hover state. The rest follows from density.

The note is paper

Panels are the desk: tinted, recessive, quiet. The editor is the one surface that advances — brightest in light, lightest in dark. Depth always points at the writing.

Tint separates, rows are objects

Panes are told apart by a step of tint, not by a rule between them. Inside a pane, every row is an inset rounded rect that lights up on hover or selection. A 1px hairline appears only where a group ends — above Trash, between menu sections. Never between rows, with one exception: an iOS inset grouped list, where the platform draws them and we follow.

Chrome arrives on demand

Drag handles, insert buttons, row overflow, folder actions: all invisible until the pointer or keyboard focus is in range. At rest the app is text and hairlines.

Accent marks persistent state

The focus ring, the active segment in a toggle, a link, the sync dot, a live text selection — things that are still true after you look away. Transient state is neutral: menu and popover highlights are only where the keyboard is. Never a saturated fill. iOS adds one case, a bare tappable word.

Rows are sized by their type

A note row is 58 because its type is 19 + 17 with 22 of air — not because 58 sits on a spacing scale. Every size is even, every icon box is square, and each pane keeps one inset for its whole column: 18 in the tree, 20 in the list, 20 on iOS.

Three UI weights: 400, 500, 600; the display face stays at 400. Selection never animates — it must feel like the row was already selected. Popups scale from 0.97 with transform-origin at the trigger, and leave in half the time they enter. 01 · Title bar

44px, frameless, whole bar is the drag region except its controls. Traffic lights inset 18px, then two 26px pane toggles. The Orb sits 8px left of the search field: the app’s own amber disc at 19px in a 26px target, flat — no gradient, no bevel, holding the workspace list and everything app-wide. It is the one saturated thing in the chrome, and it is the app mark — not an accent. The ⋯ at the far right is the open note’s own menu — never app settings.

02 · Search & create

404 × 27, optically centred on the window, not on the editor. Typing filters live; ⏎ on no match creates a note with that title in the selected folder. ⌘K focuses it.

03 · Sync dot

7px accent dot with a 3px halo, plus one word. Amber saved · dim amber writing · gray offline · red failed. It replaces the toast that used to fire on every save.

04 · Folder tree

236px. Rows 32px at 14/500 — the same type as the note list, so the two panes read as one app. Two mono labels, Library and Folders, group the column the way the list groups by time. Indent is a 12px step with a hairline guide, so five levels of nesting stay legible in a 236px column. Trash sits at the foot, away from the vault: it is a destination, not a folder.

05 · List header

38px. The folder’s name at 14/600 with its count beside it — the scope header that replaced the per-row breadcrumb. Sort is a Base UI Select rendered as a quiet text button, no field chrome until hover. New is the only raised control in the app, and it is 24px tall.

06 · Note row

58px fixed — the virtualizer depends on it. Title at 14/19 medium with the time right-aligned on the same line, then one line of the note’s own first words at 12.5/17 in --text-3. Medium at 14 is the weight that stops a title reading as body copy without shouting; 400 at 13 was too quiet against its own preview. The preview is what tells two notes with similar titles apart; the breadcrumb never came back, because the folder is already the thing you are looking at.

07 · Pins, selection, hover

Time groups — Pinned, Today, Yesterday, Earlier — give the list its rhythm, and pins become the first of them rather than a badge on a row. Selection and hover are an 8px-inset rounded rect, matching the folder rows exactly; hover swaps the time for the overflow dots.

08 · Paper

The editor is the only pure-white surface, and no rule separates it from the list — the tint step does that. Measure is 680px, centred in the pane, independent of window width. Nothing sits between the title and the first block.

09 · Block gutter

Two buttons, revealed only while the pointer is inside a block: ⠿ drags the block to reorder it and opens its menu on click, + inserts a new block below. They sit at −54px from the measure, 22 × 24 each with a 12px glyph, opacity 0 at rest. Same optical padding as every other icon button in the app. The hovered block itself takes a 2.8% wash with a 6px bleed.

10 · References

40px bar pinned to the bottom of the editor pane only. A Base UI Collapsible; expanded it grows to 300px max with its own scroll.

04b

The same shell, dark

Identical geometry, identical token names, inverted stack: paper is now the lightest surface, so depth still points at the writing. Hairlines go to white at 9%, the inset highlight on raised controls drops to 6%, and window shadow deepens. Chroma rises in dark — warmth is less visible at low lightness, so hue 75 needs about 1.7× the chroma to read as the same warm neutral. Nothing in a component file changes — only the values behind [data-theme].

Selection in dark

The neutral wash steps from 6.5% ink to 8% white — the same perceived weight against a dark ground. Row title goes to --text-1 at full strength; the metadata line stays one step down.

Recessed vs raised

In dark, inputs go darker than their panel with an inner shadow, and raised controls go lighter with a 6% top highlight. In light it is the reverse. That single rule keeps both themes legible without a second layout.

Traffic lights

Never re-tinted. macOS owns them; the title bar under them changes but the controls do not.

Rules

Title, time, and the note’s first words. One line of preview is what tells Sync conflicts — Q1 from Sync conflicts — Q2 without opening either. What did not come back is the breadcrumb: in a scoped folder it repeats the folder you are already looking at.

The preview is body text, not metadata. First ~70 characters of the rendered note with headings and markup stripped, one line, ellipsis. Never wraps to two — a row that changes height while scrolling is the fastest way to make an app feel cheap.

Time groups carry the rhythm. Pinned, Today, Yesterday, Earlier. Without them a scoped list is three hundred identical blocks; with them the eye has somewhere to land. Groups follow the active sort — sort by title and they become A, B, C.

The overflow target is 24px. A 15px glyph in a 24px rounded box at --text-2 — the same size as every other icon button in the chrome. It has two steps of its own: quiet while the row is hovered, then a 10% wash and --text-1 when the pointer is on the button itself, so it is unmistakably a target before you click.

Two washed rows never touch. Hover and selection use the same neutral family, so if they land adjacent they read as one four-line block. Hover is suppressed on the row directly above or below the selection — the pointer still works, the wash just does not draw.

Rename happens in place. No field, no border, no box. F2 makes the title itself editable and selects it; the preview line below does not move. Return commits, Escape reverts, clicking away commits.

Base UI parts: the row is a plain button in a roving-tabindex list — no component. Only the ⋯ uses Menu, and right-click opens the same menu at the cursor via ContextMenu.

Two things to watch in Base UI

Typeahead. Menu and Select capture single letters for their own type-to-select. Inside the folder rail that collides with n and with vim j/k — the rail is not a Menu, keep it a plain roving-tabindex tree.

Focus return. Every dialog and menu must return focus to the row that opened it, not to the body. After an inline rename the list takes focus back — that is already true today and is easy to lose.

Build order

Six passes, each one shippable. The app keeps running throughout: GravityUI and Base UI coexist happily as long as the tokens land first, so nothing here needs a branch that lives for weeks.

PASS 1Tokens
  • tokens.css — surfaces, text ramp, lines, accents, radius, shadow, motion
  • data-theme on <html>; delete ThemeProvider
  • Point the existing GravityUI variables at the new tokens so the old UI inherits the new palette immediately

Ships: the whole app changes colour, nothing changes shape.

PASS 2Primitives
  • Button (quiet / raised / filled), Icon set, Kbd, Chip, Banner, Skeleton
  • Base UI installed; Menu, Popover, Dialog, Tooltip wrapped once each with our material
  • isolation:isolate on the root; portal stacking verified against the Tauri title bar

Ships: nothing visible. This is the pass to not skip.

PASS 3The shell
  • Title bar, folder rail, list header, note row at 58px, virtualization
  • Row and folder menus on Base UI Menu + ContextMenu; sort on Select
  • Sync dot replaces save toasts

Ships: the app looks new. This is the pass people will judge.

PASS 4Editor chrome
  • Block gutter, format bar, slash menu, wiki picker on Combobox
  • Note appearance popover; linked-references bar on Collapsible
  • Retire selectionContextFix along with the editor’s own tooltip

Ships: the writing surface. Highest regression risk — lean on the existing editor tests.

PASS 5Dialogs & states
  • Settings, Shortcuts, About, Attachments, Trash, Move to, Workspaces, Update
  • All six empty / loading / error states
  • Last @gravity-ui/uikit import removed; scope-css.mjs deleted from the build

Ships: the dependency drops out of package.json.

PASS 6iOS
  • Stack navigation: folders → list → note, with swipe-back
  • 66px rows, 44px targets, 52px floating compose, actions sheet
  • Block toolbar above the keyboard; long-press replaces the gutter

Ships: phone parity. Android inherits the tokens with no new decisions.

Open, and worth deciding before pass 3

Windows title bar. Same layout, but the search field can no longer be window-centred with the controls on the right. Needs a decision, not a workaround.
